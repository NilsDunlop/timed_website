# Cell Health / idr0080 data reference

This document records the real-data facts used by TIMED's Phase 1 Cell Health
viewer. The data server reads the packed source files in place and exposes a
read-only virtual OME-Zarr view; it does not convert or modify the dataset. See
the [idr0080 implementation brief](../plans/idr0080-codex-brief.md) for the full
design and the later segmentation/QC contract.

## Images and packed layout

| Item | Value |
| --- | --- |
| Root | `/nobackup/proj/disk/naiss2024-5-630/personal/nilsdu/biomorph/idr0080` |
| Index | `idr0080-raw.index.parquet`: 155,520 rows, one per channel plane, representing 31,104 fields |
| Index columns | `relpath, experiment, plate, well, site, channel, offset, size, shard` |
| Image shards | Nine `idr0080-raw-SQ000146xx.tar` files beside the index; `shard` names the file |
| Tar members | `idr0080/raw/` plus `relpath`; `offset` points to the member payload |
| Planes | Single-page uncompressed TIFF, 2160 × 2160, `uint16` |
| Metadata | `metadata/metadata_idr0080.csv`: 3,456 wells and 19 columns |

The experiments `idr0080-A549`, `idr0080-ES2`, and `idr0080-HCC44` each contain
three plates. Plates 14610–14618 are unique across the experiments and are shown
as `SQ000<plate>`. Every plate has all 384 wells (rows A–P, columns 01–24), nine
sites per well, and five channels per site. A field is presented as
`<well>_s<site>.zarr`; its five channel members are contiguous in the plate's
tar shard.

Metadata joins on CSV `experiment_name, plate, address` to index
`experiment, plate, well`. It supplies the cell line, gene, guide, well type,
control category, and barcode. The inventory found a complete join for all
3,456 wells. A source survey also checked 450 planes from 90 random fields: all
had the expected shape and dtype, and every sampled tar header matched the
index.

The virtual image is an OME-Zarr 0.5 group with one array, `s0`, shaped
`[5, 2160, 2160]` in `c, y, x` order. Its chunks are `[1, 1080, 1080]`, encoded
with Blosc Zstd level 3, byte shuffle, and `typesize` 2.

## Channels and display defaults

Color mode starts with the DNA, ER, and AGP composite. Cell Health also declares
Grayscale mode, which displays one selected channel at a time with that
channel's fixed contrast window.

| Packed slot (member suffix) | Stain | Phenix / IDR channel | Color | Shown in the default composite |
| --- | --- | ---: | --- | --- |
| 1 (`_ch1.tiff`) | DNA | 1 | `1300F9` | Yes |
| 2 (`_ch2.tiff`) | ER | 2 | `2AFF1F` | Yes |
| 3 (`_ch3.tiff`) | AGP | 4 | `FF0019` | Yes |
| 4 (`_ch4.tiff`) | RNA | 3 | `2DFFFC` | No |
| 5 (`_ch5.tiff`) | Mito | 5 | `FA00FD` | No |

The packed index `channel` value identifies the packed slot, not the raw
Phenix / IDR channel. The export's `channels.csv` establishes this mapping by
high-pass correlation across 21 sites: matching correlations are at least
0.98 and every other correlation is at most 0.69. CellPrompter records use the
raw Phenix file numbers; interpreting them as packed slots was the source of
the original AGP/RNA swap.

The colors follow the hue-separated Recursion Cell Painting palette by stain.
Contrast is fixed per cell line so brightness remains comparable between wells.
Each default window is the pooled 1st to 99.9th percentile from 30 random fields
for that cell line; slider ranges cover zero to twice the largest surveyed
99.9th percentile, rounded up to 1,000.

| --- | ---: | ---: | ---: | ---: |
| DNA | 292–11,552 | 234–12,971 | 254–13,104 | 0–27,000 |

The survey measured packed slots, so its windows stay with slots 3 and 4 when

shorter 0.01 s exposure compared with AGP's 0.02 s exposure.

## Physical calibration

The Phenix acquisition indexes for all nine plates, `SQ00014610` through
`SQ00014618`, report identical X and Y resolutions of
`2.9898804047838085E-07` m at 20×. Cell Health therefore uses
`0.29898804047838085` µm/px. Metadata and scale-bar calculations retain that
full precision; only displayed labels are rounded.

## Later Phase 2 context: masks and QC

The following files are inventory context. Phase 1 neither reads nor displays
masks, and all stores remain read-only. Part C's reader rules are in the
[mask-store contract](#mask-store-contract-part-c) below; the operator's check
of all ten real stores is Appendix D.4 of the
[implementation brief](../plans/idr0080-codex-brief.md#appendix-d-cellprompter-data-contract),
and the blinded QC boundary is in [QC_EXPORT.md](QC_EXPORT.md).

- The default model, `masks/idr0080_cpsam_B90/`, covers all nine plates and all
  31,104 fields. It contains 93,312 nuclei, cell, and cytoplasm masks in total.
- Each plate has a roughly 1.34 GB mask tar, a roughly 5.7 MB write-ahead log
  with 3,456 records, a 10,368-row mask index, and a 3,456-row × 60-column QC
  Parquet table.
- `masks/cpsam_stock_R2_top999/idr0080-A549/` is a second model covering only
  plate 14610.
- Manifests declare `tar+wal/v1`, `uint16`, nuclei/cells/cytoplasm, and
  `frozen: false`. Existing `.lease` files belong to writers and must never be
  opened or touched by TIMED.
- For the checked reference field, plate 14610 well A01 site 1, the default
  model recorded 731 final nuclei, 616 cells, and 616 cytoplasm objects.

## Mask-store contract (Part C)

Part C builds the segmentation outlines on this contract. It condenses section
5.1 and Appendix D of the
[implementation brief](../plans/idr0080-codex-brief.md), with the amendments of
the [Cell Health QC brief](../plans/cell-health-qc-brief.md#5-part-c-segmentation-outlines-060)
and the operator's decisions applied. If the data ever disagrees with it, stop and
ask.

### Stores

- **Models.** Each model is a folder `masks/<model_tag>/` under the idr0080 root,
  declared in the code profile relative to the image index. Its `manifest.json`
  holds `frozen`, `schema.store_format` (`"tar+wal/v1"`), `schema.mask_dtype`
  (`"uint16"`) and `schema.kinds`. Skip folders with any other format.
- **Coverage.** `idr0080_cpsam_B90` covers all nine plates and is the default.
  `cpsam_stock_R2_top999` covers only `idr0080-A549/14610` and is offered only
  there. Both are `frozen: false`.
- **Plate files.** `<experiment>/Plate<plate>.masks.tar`, `.wal.jsonl`,
  `.index.parquet`, `.qc.parquet` and `.lease`. A model is available for a plate
  when its tar and log exist.

### Reading a store

1. **The log is authoritative.** It is UTF-8 JSON Lines, one committed field per
   complete line: `{well, site, tar_end, masks: [{kind, offset, size}, ...], qc,
   git_sha}`. The last record wins for each `(well, site)`.
2. **Unreadable lines.** A final line without a newline is a write in progress;
   ignore it. Any other line that does not parse makes the store corrupt.
3. **Committed length.** `tar_end` is the valid tar length after that field, a
   multiple of 512 that never decreases. Ignore bytes after the largest
   `tar_end`; a tar shorter than it makes the store corrupt.
4. **Members.** A mask's `offset` points at its data. The 512 bytes before it are
   a USTAR header named `<experiment>/Plate<plate>/<well>_s<site>_<kind>.tiff`
   with size `size`; verify that header on the first read from each store. Plate
   14610's first field has nuclei at 512 (146,456 bytes), cells at 147,968 and
   cytoplasm at 339,456, with `tar_end` 576,000.
5. **Payload.** A single-page, zlib-compressed `uint16` TIFF at the image
   plane's shape. 0 is background and objects are labelled contiguously from 1,
   so the largest label is the object count. Decode without casting; tifffile
   needs no `imagecodecs` for it.
6. **Snapshots.** `index.parquet` (`experiment, plate, well, site, kind, offset,
   size`) is written when a plate is finalised. Use it only as a cross-check; on
   a mismatch, log it and keep the log. Part C does not read `qc.parquet`.
7. **Readers.** Any number of readers, on any node, take no locks, never open a
   `.lease` (leftovers from finished jobs are normal) and open every file
   read-only.
8. **Revision.** `(log size, log mtime_ns, tar size)`, checked on each request.
   Rebuild the offset table when it changes, so a growing store is picked up.

### Serving outlines

- **Routes.** The listing answers any linked dataset, with no models when it
  has none (amended in 0.6.0); the other routes serve packed plates only and
  answer 404 for anything else. `GET /api/datasets/{id}/masks` lists the plate's models with `model_tag`,
  recipe, kinds, `frozen`, `created_at`, `available` and `default`.
  `GET /api/datasets/{id}/masks/{model}/{well}/{site}` returns that model's
  count per kind for one field.
  `GET /api/datasets/{id}/masks/{model}/{well}/{site}/{kind}.png?color=RRGGBB&width=2`
  returns one outline image. A missing record or kind returns 404; a corrupt
  store returns 409 with the reason. Since 0.7.0 the listing's optional `well`
  and `site` report whether each model covers that field (none listed when no
  model does), and the field routes take an optional `t`: packed masks accept
  none or 0, and any other value returns 422.
- **Outlines.** An outline pixel is a non-zero label that differs from any
  4-neighbour, with edges padded. A width of 1 to 4 dilates the outline by width
  minus one pixels, using numpy shifts rather than SciPy.
- **PNG.** A 1-bit indexed PNG at plane size: colour type 3, a two-entry palette,
  and a `tRNS` chunk that makes index 0 transparent. Rows are packed with
  `numpy.packbits`, prefixed with filter byte 0 and compressed with `zlib`. The
  ETag comes from the store revision, offset, size, kind, colour and width;
  responses send `Cache-Control: private, max-age=3600`.
- **Caches and threads.** Decoded labels sit in a byte-bounded LRU (512 MB by
  default, `serve --mask-cache-mb`; about 9.3 MB per mask) and encoded PNGs in a
  second one (256 MB). All mask work runs in worker threads.

### Viewer

- **Panel.** A Segmentation panel in the viewer controls, which the QC field view
  shares, appears when the plate has masks. It offers a model selector (default
  first), a "May still change" badge when `frozen` is false, per-kind toggles
  (Nuclei `FFD400`, Cells `FFFFFF`, Cytoplasm `FF8C00`; all off by default),
  outline width (default 2) and opacity, and a count line such as
  "731 nuclei · 616 cells" taken from the masks' own labels.
- **Drawing.** One deck.gl `BitmapLayer` per visible kind, passed through
  VivCanvas's `overlayLayers` from `lib/viewerOverlays.ts`, with bounds
  `[0, H, W, 0]` so it aligns in pixel coordinates. Each comparison source gets
  layers for its own field; the settings are shared. "Image ready" keeps
  describing image pixels only: outlines are a sanity check on the masks.
- **URL preset.** `outlines=nuclei,cells` and `model=` start a view with those
  kinds switched on. They have no effect on TIMED.

**Operator check.** On plate 14610, well A01, site 1, 731 nucleus and 616 cell
outlines align with the image, the stock model is offered only on 14610, and
outline timings are recorded.
